# Обоснование конфигурации инфраструктуры

## Выбор ресурсов и параметров

### Виртуальная машина

**Параметры: 2 vCPU, 4GB RAM**

**Обоснование:**
- 2 vCPU обеспечивают достаточную производительность для базовых задач и тестирования
- 4GB RAM достаточно для работы операционной системы Ubuntu и базовых приложений

### Диск

**Параметры: 20GB SSD (network-ssd)**

**Обоснование:**
- 20GB достаточно для установки операционной системы Ubuntu 22.04 LTS и базовых приложений
- Network SSD обеспечивает высокую производительность и надёжность
- Автоматическое резервное копирование и репликация данных
- Тип "network-ssd" подходит для большинства задач и обеспечивает баланс между производительностью и стоимостью

### Сетевая инфраструктура

#### VPC и подсети

**Обоснование:**
- VPC сеть обеспечивает изоляцию инфраструктуры
- Публичная подсеть (10.0.1.0/24) для компонентов, требующих прямого доступа из интернета
- Приватная подсеть (10.0.2.0/24) для виртуальной машины, обеспечивающая безопасность

#### NAT Gateway

**Обоснование:**
- NAT Gateway обеспечивает исходящий интернет-доступ для виртуальной машины в приватной подсети
- Позволяет виртуальной машине обновлять пакеты, загружать зависимости без прямого доступа из интернета
- Использование shared_egress_gateway для экономии ресурсов и снижения стоимости
- Таблица маршрутизации направляет весь исходящий трафик из приватной подсети через NAT Gateway
- Обеспечивает безопасность: виртуальная машина может инициировать исходящие соединения, но не может принимать входящие из интернета

**Настройки NAT:**
- Использование shared egress gateway снижает стоимость по сравнению с выделенными NAT-инстансами
- Автоматическое масштабирование пропускной способности
- Высокая доступность благодаря распределённой архитектуре Yandex Cloud

## Декларативный подход

### Причины использования декларативного подхода

1. **Идемпотентность**
   - Terraform гарантирует, что повторное применение конфигурации приведёт к желаемому состоянию
   - Исключает ручные ошибки и расхождения между окружениями

2. **Версионирование**
   - Инфраструктура описывается в коде, что позволяет использовать системы контроля версий
   - Возможность отслеживания изменений и отката к предыдущим версиям

3. **Повторное использование**
   - Конфигурация может быть использована для создания идентичных окружений
   - Легко адаптировать под разные проекты, изменив переменные

4. **Документирование**
   - Код инфраструктуры служит живой документацией
   - Легко понять текущее состояние и зависимости между ресурсами

5. **Автоматизация**
   - Интеграция с CI/CD пайплайнами
   - Автоматическое развёртывание и тестирование изменений

6. **Безопасность**
   - Централизованное управление доступом через системы контроля версий
   - Code review для изменений инфраструктуры
   - Аудит всех изменений

## Infrastructure as Code (IaC) и его преимущества

### Воспроизводимость

**Как IaC способствует воспроизводимости:**

1. **Идентичные окружения**
   - Одна и та же конфигурация Terraform может создать идентичные окружения для разработки, тестирования и продакшена

2. **Быстрое восстановление**
   - В случае сбоя инфраструктуру можно быстро восстановить из конфигурации
   - Не требуется ручное воссоздание сложных настроек

3. **Документированное состояние**
   - Текущее состояние инфраструктуры всегда известно и задокументировано в коде
   - Новые члены команды могут быстро понять архитектуру

4. **Тестирование изменений**
   - Изменения можно протестировать на копии окружения
   - Снижение риска ошибок при развёртывании

### Масштабируемость

**Как IaC способствует масштабируемости:**

1. **Горизонтальное масштабирование**
   - Легко добавить новые виртуальные машины, изменив количество в конфигурации
   - Автоматическое создание идентичных инстансов

2. **Вертикальное масштабирование**
   - Изменение ресурсов (CPU, RAM, диск) требует только обновления переменных в конфигурации
   - Terraform автоматически применит изменения

3. **Модульность**
   - Конфигурация разбита на логические части (сеть, вычисления)
   - Легко масштабировать отдельные компоненты независимо

4. **Автоматизация масштабирования**
   - Использование переменных для параметризации размеров ресурсов
   - Легко адаптировать под изменяющиеся требования

5. **Управление зависимостями**
   - Terraform автоматически управляет зависимостями между ресурсами
   - Правильный порядок создания и обновления ресурсов (сначала сеть, потом VM)
